## 我做了什么
- **4 题小测 + 2 道额外题全部通过**：
  1. **UART TX 状态机默写**：IDLE/START/DATA/STOP 四状态 + 转移条件 + 输出动作。第一版答成了"系统数据流"（RX → loop → TX），订正后抓准"TX 模块**内部**自己怎么走"
  2. **阻塞 vs 非阻塞赋值**：`=` 逐条立即生效（有顺序依赖）；`<=` 同一时钟沿先采样旧值、块结束统一更新。用 `a=b; b=a` 交换例子推演：阻塞版一个沿后 a、b 都变成原 b（交换失败），非阻塞版才交换成功
  3. **分频计算**：1 bit = 8680 ns ÷ 时钟 20 ns = 434 周期，数 0~433 共 434 个周期翻转；实际波特率 50M/434 ≈ 115207.4，误差 ≈ 0.006%（远小于 ±2% 容差，达标）
  4. **0x33 帧电平图**：LSB 在前 → 线上依次 1100 1100（高高低低高高低低），起始低 8680 + 数据 69440 + 停止高 8680 = 总长 86800 ns，用 Python（matplotlib）画波形图核对一致，见 `day13_uart_frame_0x33.png`
- **额外题**：打拍链阻塞版 d0/d1 差 0 拍（同步器失效）vs 非阻塞差 1 拍；9600 波特率分频 = 5208 周期、实际波特率 9600.6 bps

## 我学到的
- **状态机描述模板**：每个状态 = 转移条件 + 输出动作，缺一不可；模块内部状态机 ≠ 系统数据流，两个层次别混
- **阻塞/非阻塞病根一句话**：阻塞赋值的顺序依赖让"读旧值"变成了"读新值"——同步器打拍链必须用 `<=`，否则两拍变一拍，亚稳态照样传
- **分频值单位**：434 是"时钟周期个数"不是时长；bit 时长才用 ns（8680 ns）
- **误差公式**：(实际波特率 − 标称波特率) ÷ 标称波特率

## 今天我踩的坑（都改过来了）

- **分频值单位写错**：5208 说成 ns，实际是 5208 个时钟周期
