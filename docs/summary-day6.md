## 今天我答错的（都改过来了）
- 状态名："复位/记录" → IDLE/START/DATA/STOP（IDLE 是"空闲等着"不是"复位"）
- rx_flag 当 TX 的转移裁判 → 看错模块了，TX 的触发是外部 tx_flag，节奏是 baud_pulse
- "跟时序有关的就是 reg" → 错！谁驱动它决定：always 赋值的 = reg，子模块/assign 驱动的 = wire
- "1bit = 两个位宽" → 1 bit = 一个电平持续 434 周期（时间概念，不是宽度）
- 组合块 always@(baud_pulse) → 一个脉冲触发两次（升降沿都敏感）cnt 每脉冲 +2；必须 @(*)
- 时序块里给 input 赋值（clk/tx_flag/tx_data）→ input 只读，复位只复位内部状态
- 状态编码撞码（IDLE 和 STOP 都编 2'd1）→ 状态编码必须两两唯一（第 4 天老坑重现）

## 我今天真正学会的（按重要性）
1. **快照/打包思想**（最重要）：发送前把 tx_data 锁进 shift 缓冲，发送期间用副本——因为一帧要 4340 个时钟周期，边发边读外部数据会被中途修改导致帧错乱
2. **时钟使能（含双沿陷阱）**：想"在脉冲时动作"是直觉，但硬件实现必须"clk 触发 + 脉冲当许可开关"：
   - `always@(baud_pulse)` → 脉冲的**上升沿和下降沿都触发**，每个脉冲执行两次（cnt 每脉冲 +2，数不到 7）
   - `always@(posedge clk)` + `else if(baud_pulse)` → clk 每 20ns 触发一次**检查**，但只有 baud_pulse=1 的那一拍才**执行**——每个脉冲只执行一次
   - 同样的"脉冲驱动"直觉，两种写法差 2 倍执行次数——**触发源（clk）和条件（脉冲）分开**才是对的
3. **一个信号只有一个驱动者**：input 只读、wire 归子模块管、reg 归 always 管
4. **走一步看一步**：写代码不用一次想全所有信号——每写一块 → 补声明 → 编译验证，循环推进
5. **1 bit 是时间概念**：一个电平持续 434 周期（8680ns），不是"位宽"
6. **状态转移条件要"状态 + 条件"双限定**：`if(state == IDEL && tx_flag)` 而不是 `if(tx_flag)`——只写 tx_flag，任何状态下（比如 STOP 时）请求又拉高就会误跳 START，状态机不稳定。每个转移都要问："**在哪个状态下** + **什么条件**成立才跳？"
