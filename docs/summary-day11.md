## 我做了什么
- **亚稳态**：D 触发器的输出必须是 0 或 1，但如果 D 在时钟沿附近的"建立时间/保持时间"窗口内变化，触发器采样的就是一个不确定值，输出会悬在 0 和 1 中间震荡（亚稳态），过一段时间才随机解析成 0 或 1。解析方向看运气、解析时间不确定，只是概率随时间指数衰减、永远不会归零——所以电路里"亚稳态消除"是不存在的，只能"降低概率"。
- **两级同步器**：把一个异步信号送进**串联的两个触发器**。第一级允许它亚稳态，第二级在下一个时钟沿才采样第一级的输出——给了第一级整整一个时钟周期去解析。解析不完的概率呈指数下降，两个周期后几乎必然干净。代价是信号被延迟两个时钟周期。
- **异步复位、同步释放**：复位信号 rst_n 拉低时必须立刻生效（异步复位，不然时钟停摆时复位就失效了）；但释放（拉高）不能随便放——如果释放刚好撞上时钟沿，所有触发器在同一时刻有的已复位有的没复位，状态机会从乱七八糟的状态开机。所以释放要交给同步器：先两级打拍，让"复位解除"这件事只发生在时钟沿上，而且全系统同一个沿一起解除。
- **自己写 rst_sync.v（4 版迭代，线索式批改）**：
  - v1：只有复位分支没有 else、裸 always 没有敏感列表、端口列表用分号、output 漏 reg
  - v2：敏感列表对了（posedge clk or negedge rst_n）、知道要两个寄存器，但链子方向反了（d0 从输出 rst_n_sync 往回取）、begin/end 配对乱、output reg 还是漏
  - v3：output reg 补上、链子方向对了（rst_n → d0 → d1）、结构干净，但 rst_n_sync 自己当了第三个寄存器，只在复位分支清 0、else 没人给它赋值 → 释放后永远 0，里面三个子模块被按死在复位（编译能过、仿真必挂的真 bug）
  - v4 ✅ 通过：两级打拍（d0<=rst_n; d1<=d0）+ 组合输出（assign rst_n_sync = d1），正好 10 行
- 例化进 uart_top：同步后的 `rst_n_sync` 接给 uart_rx / uart_tx / uart_loop 三个子模块。外部 rst_n 一拉低，内部立刻复位；外部 rst_n 拉高后，内部复位还要再等两个时钟沿才解除——这两个沿就是给亚稳态"留的解析时间"。

## 我学到的
- **建立时间/保持时间**：触发器采样要求在时钟沿**之前**数据稳定建立时间、**之后**再保持保持时间；这个窗口里变化 → 亚稳态。
- **亚稳态的本质**：不是"输出坏了"，而是"输出在一段时间内既不是 0 也不是 1，之后随机落定"；数字电路里没法根除，只能给它时间。
- **两级同步器为什么是"降低概率"**：第一级亚稳态后有一个整周期解析，解析不完的概率指数级小（MTBF 可以到几年），但永远不是零——就像丢硬币连续 100 次正面概率极小但不是不可能。
- **异步复位为什么异步**：复位是保命信号，时钟都可能停（比如上电瞬间），所以它必须不依赖时钟立刻生效。
- **同步释放为什么同步**：解除复位如果和时钟沿撞车，全系统触发器"各醒各的"，状态机从乱状态启动；同步释放 = 全系统约好在同一个沿一起醒。
- **第 10 天 0xd5 的重新认识**：之前只在 TB 里加 `#100` 间隔（测试侧打补丁：让打拍寄存器先采到空闲高）。今天这个 bug 的**设计侧**根源是"复位释放没有同步"——TB 补丁只对这个激励有效，真正的修复是 RTL 加复位同步器，不管外部复位什么相位释放，内部都对齐到沿。
- **$time 的单位陷阱（检查器翻车）**：临时 TB 里我写检查器判断"释放时刻 % 20000 == 10000"（以为 $time 是 ps），实际 `$time` 返回的是 **ns 整数**（130 而不是 130000），第一次跑 CHECK FAIL 是我检查器的 bug、不是 DUT 的 bug；`%t` 打印会把 ns 值按精度展开成 ps（打印 130000）。改成 `% 20 == 10` 后全 PASS。
- **画图脚本的段索引陷阱**：画波形时"边沿时刻列表 + 哪些段为高"的索引算错一拍（high_from=[2,4] 应为 [1,3]），画出来的 d0/d1 高低段正好反了，被 image-vision 识图抓出来，改成 [1,3] 后与仿真时间点完全对上。
