# 第 10 天总结：$display / $monitor + 自动比对 TB（2026-08-17）

## 今日目标
HDLBits → Verification → Writing Testbenches（clock / tb1 / and / tb2）+ 把第 9 天环回 TB 升级成自动比对（收一帧、比一帧，报 PASS/FAIL）。完成标志：TB 打出 "PASS: 0x55" 这类带期望值和实际值的行。

## 我做了什么
- **HDLBits 五题刷完**：clock（无端口 TB + 时钟生成）、tb1（initial 摆波形）、and（例化 andgate 穷举 4 种组合）、tb2（例化 q7 按波形图给 clk/in/s）、tff 彩蛋（例化 tff：时钟 + 同步复位 + 翻转使能，把前四题知识点全串起来）。题名勘误：计划写的 tb_and/tb_mux2 站点上不存在，实际叫 AND gate / Testbench2。
- **tff 三连踩坑**：①`#5 reset = 0` 和第一个上升沿（t=5）撞车——同步复位要靠上升沿采样，复位拉低必须躲开沿（盖住沿）②`#10 t = 1` 在 t=15 又撞上升沿 ③t 拉 1 后没拉回 0，q 会一直翻。改成：复位保持到 t=10（跨过 t=5 沿）、t 在 t=14 拉高（躲开 t=15 沿）、t=19 拉低（躲开 t=25 沿）→ 通过。
- **自己写自动比对 TB（3 版迭代）**：基于第 9 天 TB，加了 `expected_byte`（期望值）+ `pass_cnt`/`err_cnt`（计分）+ `task send_byte`（把 9 行发帧打包）+ 每帧四步曲（记期望 → 发 → 等 rx_done → if 比对 + $display 报 PASS/FAIL）+ tx_busy 握手（等回显发完再发下一帧）+ 期末总结。
- **自动比对 TB 抓到一只真 bug**：第 1 帧 FAIL（exp 0x55 != got 0xd5）。根因：`#100 rst_n = 1` 和 send_byte 第一行 `rxd = 0`（起始位）同一时刻——RX 的双寄存器打拍检测器被复位清零成 0，等不到"先 1 后 0"的下降沿，起始位漏检，RX 到帧中间错位采样出 0xd5。修法：复位释放后加 `#100` 间隔，让打拍寄存器先采到空闲高。修完三帧全绿：PASS 3, FAIL 0。
- **背靠背实验（临时 TB，跑完已删）**：不加握手连续发 3 帧，三个发现——
  1. **loop 真丢帧**：帧 2 收完时 loop 还在 WAIT_TX 忙第 1 帧回显（铁证：rx_start_flag 触发但 state=2），帧 2 的回显被忽略；
  2. **TB 有盲区**：帧 2 没回显但 TB 照报 PASS——它只比了 RX 的接收（rx_data），没比回显输出（txd）。回显只发出 1 帧，TB 却报 3/3 PASS；
  3. **事件驱动等待会挂死**：`@(posedge tx_busy)` 等一个永远不会来的回显 → 仿真卡死 → 用 watch dog（600µs 超时 + $finish）才救回来。真实验证里必须有超时机制。

## 我学到的
- **$display = 到点打卡，$monitor = 哨兵站岗**：$display 执行到这一行才打一次，打印次数 = 所在块被触发的次数；$monitor 只要被监视的变量一变就自动打，不变就一直蹲着，且全程只能有一个。**判对错靠 if 比较，报告结果靠 $display**——$monitor 只会复述变量，不会判定。
- **自动比对 TB 需要四件套**：①期望值（发之前先记好"这帧应该收到什么"）②收卷时机（等 rx_done，不能在固定延时后读——会读到没收完的半截值）③记分（pass_cnt/err_cnt）④期末评语（总结 $display）。
- **task vs initial**：initial 是仿真启动自动跑一次的块；task 是"随叫随演"的子程序，必须被调用才跑、调用几次跑几次、能带参数、能写 #延时、能直接改模块里的变量（≈C 的 void 函数）。
- **发帧 task 里"先摆电平再计时"**：`rxd = 0; #8680;` = "从此刻起保持低电平 1 bit 时间"。反过来写（先 # 后赋值）帧会整体推迟一拍。10 行正好 10 bit = 一帧 86800ns。
- **所有输入信号的变化都要躲开时钟沿**：沿前稳定、沿后保持——TB 激励和 DUT 时钟错开，否则出现竞态（tff 三连 + 复位撞车都是这个思想）。
- **复位释放后要等一拍再发数据**：RX 的下降沿检测器在复位时被清 0，如果起始位和复位释放同时发生，打拍链从 0 起步，永远等不到 1→0 跳变。这也是第 7 天"激励顺序：先复位 → 再数据"坑的变体——重构 task 时把第 9 天 TB 里 8680ns 的间隔弄丢了。
- **自动比对的价值**：差一个沿的 bug，人眼看波形很难发现，TB 一比对就原形毕露（0xd5 当场现形）。
- **TB 的检查点选在哪、比什么，比会不会写 $display 重要得多**：只查内部信号（rx_data）会漏掉输出路径（回显）的 bug。真验证要对着 DUT 的输出端口比对（全链路），这就是以后 SV/UVM 里 scoreboard 的雏形。
- **看门狗（watchdog）**：事件驱动等待可能永远等不到（DUT 没按预期工作），TB 要挂一个超时机制：`initial begin #超时 $display("TIMEOUT"); $finish; end`。

## 我问的问题
1. integer 是啥？→ 32 位有符号整数，C 的 int；TB 数数用，RTL 里不用（reg 才是指定位宽的电路变量）
2. task 和 endtask 是干嘛的，跟 initial 什么区别？→ 随叫随演 vs 开场自动演
3. send_byte 什么时候触发？→ 执行到调用那一行才触发，阻塞式，演完回到调用点
4. 为什么 task 里 #时间写在 rxd 后面？→ 先摆电平再计时一拍，每个电平保持 1 bit
5. 我要加什么变量、这些变量干嘛、要对比哪些东西？→ 期望值/计分 + rx_done 触发 + rx_data 比对
6. （tff）复位要拉高多久？→ 同步复位要在时钟沿时是高的，跨过至少一个沿
7. （自动比对）需要哪些部件？→ 期望值、收卷时机、记分、总结
