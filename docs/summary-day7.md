# 第 7 天总结：UART TX 仿真通过 + 第一篇博客（2026-08-14）

## 今日目标
给第 6 天写的 UART TX 模块搭测试平台（TB），跑仿真，验证完整一帧，写第一篇博客。

## 我做了什么

**热身三问**：端口四输入一输出答对；tx_flag 触发时机答对（要点：使能才动，脉冲撞上才出发）；0x55 的帧先答错（"传输八位 0"），经线索自查改对成 10101010（LSB 在前），还发现 0x55 整帧正好 0-1 交替的妙处。

**自己写 TB，五版迭代**：
1. 第一版 `reg txd` → 错。学了硬规矩：**模块实例的 output 端口只能接 wire**，类型由"谁驱动"决定，不由"以后再说"决定
2. 时钟写成 `clk = clk` → 等于没写，仿真死寂。翻转要用 `~`
3. `$finish #5000` → 太短，连 1 bit（8680ns）都发不完。算清一帧 = 10 × 8680 = 86800ns 后改成 200μs
4. 激励顺序乱：flag 在复位窗口内白按。正确顺序：**先释放复位 → 再装数据 → 后按发车铃**
5. `8'd01010101` → 十进制 101 万，溢出截断成 0xB5；`8'b` 才是二进制。flag 只按 100ns → 状态机听不见，要按满 ≥1 bit 时间

**仿真**：第一次截图 zoom 到最后一纳秒，啥都看不见（第 5 天老坑重现：窗口太窄看时钟是直线）；Ctrl+F 后完整一帧出现。ModelSim 闪退一次，重启后恢复，没丢任何东西。

**帧对齐核对四问**：起始位/数据序列/停止位/全帧时长，全部答对（数据序列 10101010 一次对）。还发现了 20ns 偏差的秘密：**baud_pulse 是寄存器输出，uart_tx 晚一个时钟沿才动作**——读 Log 要读 txd/state 变化的那一行，不读 baud 上升的那一行。

## 我学到的
- **TB = 测试平台**（喂时钟/复位/激励，观察 DUT）；**DUT = 被测模块**；TB 是仿真顶层，没有端口 → `module 名;` 直接分号
- **initial 块**：按顺序执行；`#延时` 卡住执行流；只跑一次；多个块同时从 t=0 并行开始
- **20ns = 50MHz 时钟周期**（#10 翻转半个周期）；1 bit = 434 周期 = 8680ns；一帧 = 86800ns
- **$time 单位是 ps**：`timescale 1ns/1ps` 下按精度返回，Log 读数 ÷1000 才是 ns
- **游标点击有精度误差**（点歪 324ns 的教训），$monitor 时间戳才是铁证
- **激励设计纪律**：先货后令（数据摆好再拉 flag）；flag 要盖过采样时刻
